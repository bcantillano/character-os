## What We Learned

- Stub spine is not enough for believability — OpenAI dialogue immediately feels more character-like
- Interpreter labeled-line format works with gpt-4o-mini when prompts demand exact keys
- Memory bugs / recall: prior-session SQLite facts + prompt injection; thoughts vs spoken can differ
- First transcript at `docs/demos/2026-07-15-first-redbeard-conversation.md`
- Backend flow for each user line: CLI → `UserMessageEvent` → `ConversationInterpreter` (LLM #1) → `InputInterpretedEvent` → `BrainOrchestrator` Reflect (state nudge + persist) → `StateChangedEvent` → `DecisionEngine` (rule-based `SPEAK` intent) → `BehaviorExecutor`/`SpeakAction` (LLM #2 thoughts) → `ThoughtsGeneratedEvent` → `ResponseGenerator` (LLM #3 dialogue) → `ResponseReadyEvent` → CLI print + Remember persist
- Modules communicate only via the event bus; Decision produces intent, Behavior executes; Decision does not call OpenAI today
- Text sources in one turn: user string; SQLite long-term memory; YAML personality/goals/knowledge; runtime drives; session conversation turns; thoughts monologue injected into response prompt
- “Hunger” → treasure-map talk is not a special case — response prompts always carry active goals + world knowledge, so the model bridges the cue to character wants
- ~3 OpenAI calls per user message; free mini-tier still the right development default
