Character OS

Characters that remember — not chatbots that answer.

A Python framework for believable interactive characters: personality, memory, emotion, and goals on an event-driven brain.

View on GitHub See how it works

The idea

Most LLM demos feel like assistants. Character OS asks a different question: can software make someone feel they met a character — with motives, memory, and a point of view?

The brain is the product. Embodiment (CLI today, voice, vision, or robots later) plugs into the same event bus without rewriting the lifecycle.

Architecture

Every turn follows one loop. New inputs publish events; they never bypass the pipeline.

  1. Observe
  2. Interpret
  3. Reflect
  4. Decide
  5. Act
  6. Remember

  • Event bus

    Modules publish and subscribe — decision produces intent; behavior executes action. No tangled cross-module calls.

  • Data-driven packs

    New characters are YAML + Markdown prompts under characters/ and shared worlds under worlds/. Content stays configuration, not code.

  • Provider-agnostic LLM

    Stub and OpenAI providers behind one interface so the brain can be tested without burning tokens — then run live when it matters.

What I built

Phases 1–2 are demo-ready: text brain, voice out, and an authoring studio — all in Python.

Character brain

Persistent long-term memory, emotional drives, goals, internal thoughts, and relationship trust/familiarity across sessions.

Voice (TTS)

Character voice profiles, sentence-chunked playback for lower time-to-first-audio, and speech-text normalization for dialect.

Character Studio

CLI + optional web UI to create/edit packs, validate YAML, inspect memories, and stage-debug a single message through the lifecycle.

Ops for iteration

/reset confirm, preference-fact merge, and probe-driven prompt passes so companion tone can be tightened against live OpenAI transcripts.

Prompting as craft

Personality is not one system prompt. It is pack-level Markdown, examples, and hard rules iterated against real conversations.

Absolute “never ask questions” made a fresh companion feel curt. Measured curiosity — introduce on first hello, then a question cooldown — restored warmth without sliding into interview mode.

Lesson from Lumen probe loops (work-share + food scripts)
  • Good/Bad reply examples outperform vague style adjectives
  • Memory honesty rules stop “I remember you” when the store is empty
  • Food and preference facts need both prompt rules and code merge paths
